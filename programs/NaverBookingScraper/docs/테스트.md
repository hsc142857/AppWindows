# 테스트 방법 (Mac · Windows)

지금 테스트할 수 있는 것은 **GUI 관리 창**과 **CLI**입니다 (인증키 저장, 업체 확인, 서버 조회, 업로드 미리보기).
Chrome 확장 수집과 트레이 상주는 구현 후 이 문서에 추가합니다. GUI와 CLI는 같은 인증키·데이터 폴더를 씁니다.

> 업로드는 **`--dry-run`(미리보기)으로 먼저** 확인하세요. dryRun은 서버 DB에 쓰지 않습니다.
> `--dry-run` 없이 `import`하면 개발 서버 DB에 실제로 등록·취소됩니다.

## 공통 준비

- Motospec 개발 서버 실행 (`http://localhost:3000`, 모든 네트워크 주소에서 접속을 받음)
- Motospec 탑바 «인증키»에서 발급한 `msvi_…` 키
- 샘플 데이터: [`testdata/sample-reservations.json`](../testdata/sample-reservations.json)
  (기존 예약 1, 새 예약 1, 서버에 없는 예약 취소 1, 일반전화 오류 1)

## Mac — GUI

```bash
cd programs/NaverBookingScraper
make app
open dist/NaverBookingScraper.app
```

1. 처음 실행: 서버 주소는 비워 두면 `http://localhost:3000`, 인증키 입력 → **확인하고 저장**
2. 상단에 **업체명**(예: MRK모토라드)이 보이는지 확인
3. **예약 조회**: 날짜를 2026-10-20으로 → 예약 표, ◀ ▶로 날짜 이동
4. **예약 찾기**: `1234567890`
5. **가져오기**: `testdata/sample-reservations.json` 선택 → **미리보기**(저장·전송 없음)로 결과 확인.
   **가져와서 전송**은 이 PC에 저장하고 **개발 서버 DB에 실제로 씁니다** → **전송 현황**으로 이동.
6. **전송 현황**: 서버가 처리한 예약만 **전송 완료**에, 나머지는 빨간 테두리의 **미전송**에 사유와 함께
   (샘플이면 완료 2 · 거부 2: 일반전화 번호, 서버에 없는 예약 취소).
   서버를 잠시 끄고 가져오면 **전송 실패**로 나오고, 서버를 켜면 1분 안에 자동으로 완료로 옮겨집니다.
7. **설정**: 주소만 바꿀 때는 인증키 칸을 비워 두면 저장된 키를 유지합니다. **인증키 삭제** 후 다시 열면 설정 화면부터 시작합니다.

## Mac — CLI

```bash
cd programs/NaverBookingScraper
make test                       # 단위 테스트 (가짜 서버, 실제 서버 불필요)
make cli                        # dist/naverbookingscraper-cli

dist/naverbookingscraper-cli api set          # 주소: Enter(=http://localhost:3000), 인증키 입력 (화면에 안 보임)
dist/naverbookingscraper-cli status           # 서버 연결 · 인증키 · 업체명
dist/naverbookingscraper-cli visits 2026-10-20
dist/naverbookingscraper-cli visit 1234567890
dist/naverbookingscraper-cli import testdata/sample-reservations.json --dry-run
```

- 키는 `~/Library/Application Support/NaverBookingScraper/api.json`에 저장됩니다 (Mac은 암호화 없이 0600 권한).
- **처음 실행처럼** 시험하려면 데이터 폴더를 따로 지정하세요:
  `NAVERBOOKINGSCRAPER_HOME=/tmp/nbs-test dist/naverbookingscraper-cli status` → 키를 그 자리에서 한 번 묻습니다.
- 처음부터 다시: `dist/naverbookingscraper-cli api clear` (키와 업체 정보 삭제)

## Windows (Parallels VM 또는 같은 공유기의 PC)

### 1. Mac에서 배포본 만들기

```bash
cd programs/NaverBookingScraper
make build                      # dist/NaverBookingScraper-windows-amd64.zip
```

zip 안: `NaverBookingScraper.exe`(GUI, 아이콘·DPI 매니페스트 포함), `naverbookingscraper-cli.exe`, `sample-reservations.json`, `README.txt`(사용법).
zip을 Windows로 옮겨 압축을 풉니다 (Parallels면 `\\Mac\Home\…\dist`에서 바로 복사).

### GUI 실행

1. `NaverBookingScraper.exe` 더블클릭. 서명되지 않은 exe라 **"Windows의 PC 보호"**가 뜨면 [추가 정보] → [실행].
2. WebView2 필요 (Windows 11 기본 설치, Windows 10은 없으면 설치 안내가 뜸).
3. 설정 화면에서 서버 주소 `http://<Mac IP>:3000`(아래 2번 참고), 인증키 입력 → 상단에 업체명 확인.
4. 이후는 Mac GUI와 같습니다 (전송 현황 · 서버 예약 · 예약 찾기 · 가져오기 · 설정).
5. `%LOCALAPPDATA%\NaverBookingScraper\api.json`에 평문 키 없이 `token_dpapi`만 있는지 확인.

### 2. Windows에서 Mac 개발 서버 주소 확인

Windows의 `localhost`는 Windows 자신이므로 **Mac의 IP**로 접속합니다.

| 환경 | 서버 주소 |
|---|---|
| 같은 공유기의 PC, Parallels "Bridged" 네트워크 | `http://<Mac IP>:3000` — Mac에서 `ipconfig getifaddr en0` (2026-10-19 기준 `172.30.1.58`) |
| Parallels "Shared" 네트워크 (기본) | `http://10.211.55.2:3000` (Parallels가 정한 Mac 쪽 주소) |

PowerShell에서 접속 확인 — **401이 나오면 정상**입니다 (서버에 닿았고 키만 없는 상태):

```powershell
curl.exe -s -o NUL -w "%{http_code}`n" http://172.30.1.58:3000/api/visit/import-external
```

응답이 없으면: Mac 방화벽에서 node의 들어오는 연결을 허용했는지, Mac IP가 바뀌지 않았는지 확인하세요.
http 접속은 개발용으로 localhost와 사설망 IP(10.x · 172.16~31.x · 192.168.x)에만 허용됩니다.

### 3. CLI로 실행 (PowerShell 또는 Windows Terminal)

```powershell
.\naverbookingscraper-cli.exe api set http://172.30.1.58:3000   # 인증키 한 번 입력 (화면에 안 보임)
.\naverbookingscraper-cli.exe status
.\naverbookingscraper-cli.exe visits 2026-10-20
.\naverbookingscraper-cli.exe import .\sample-reservations.json --dry-run
```

- 한글은 프로그램이 콘솔을 UTF-8로 바꿔 출력합니다 (오래된 cmd.exe도 됨).
- **DPAPI 암호화 확인**: 키가 평문이 아니라 `token_dpapi`로 저장되어야 합니다.
  ```powershell
  type $env:LOCALAPPDATA\NaverBookingScraper\api.json
  ```
  다른 Windows 사용자로 로그인하면 이 키를 읽지 못하고 "복호화할 수 없습니다"가 나와야 정상입니다.
- Mac IP가 바뀌면 주소만 다시 설정하세요. 인증키 칸에서 **Enter**를 누르면 저장된 키를 그대로 씁니다:
  `.\naverbookingscraper-cli.exe api set http://<새 IP>:3000`

## 확인 목록

| 항목 | 기대 결과 |
|---|---|
| `api set`에 틀린 키 | "인증키 확인 실패 — 저장하지 않았습니다 (401)" |
| `api set`에 맞는 키 | "업체: MRK모토라드" 표시, 이후 다시 묻지 않음 |
| `status` | 서버 연결·권한·가린 키(`msvi_****…`)·업체명 |
| `visits 2026-10-20` | 맨 위에 업체명, 그날 예약 표 (시각은 서울 기준) |
| `import … --dry-run` | "[미리보기] MRK모토라드에 쓰지 않았습니다", 건별 등록/수정/오류가 입력 순서대로 |
| GUI 가져와서 전송 | 서버가 처리한 건만 "전송 완료", 나머지는 "미전송"에 사유와 함께 |
| 서버를 끄고 가져오기 → 다시 켜기 | "전송 실패 — 자동 재시도" → 1분 안에 "전송 완료"로 이동 |
| 다른 업체 키로 `api set` | "⚠ 인증키의 업체가 바뀌었습니다: A → B" |
| Windows `api.json` | `token_dpapi`만 있고 평문 `token` 없음 |
